# Week 4 Code

Week 4 converts the first three weeks into interview-ready and application-ready materials. It does not add another dataset or pretend that a generated template is a completed human interview, timed test, recording, or job application.

## Run order

Run one script at a time from the project root in the existing Miniconda environment:

```bat
cd /d "C:\Users\17860\Desktop\date analysis"

python code\day22_sql_timed_test.py
python code\day23_end_to_end_analysis.py
python code\day24_portfolio_pack.py
python code\day25_data_interview.py
python code\day26_ai_interview.py
python code\day27_resume_versions.py
python code\day28_project_presentation.py
python code\day29_weakness_remediation.py
python code\day30_final_acceptance.py
```

## Day mapping

### Day 22: SQL timed test

Four questions cover retention, funnel, per-group Top N, and anomaly indicators. The script verifies the answer key and creates a rubric, but you must complete a separate 90-minute attempt and record your score.

### Day 23: four-hour end-to-end simulation

Reads the existing raw-derived DuckDB model, rebuilds the core result views, produces a summary chart and workbook, and writes a seven-section report from actual project facts.

### Day 24: portfolio packaging

Creates a curated portfolio README, data dictionary, limitations, asset manifest, project structure, and a workbook listing presentation artifacts.

### Day 25: data analysis interview

Creates 20 questions covering metrics, SQL, retention, funnels, anomalies, experiments, causality, modeling, and project explanation.

### Day 26: AI interview

Creates 20 questions covering overfitting, AUC, feature engineering, leakage, embeddings, Transformer, LoRA, PyTorch, deployment, monitoring, Spark, and CPU-only LLM work.

### Day 27: targeted resumes

Creates a base resume and versions for ByteDance, Pinduoduo, and Bilibili. Metrics are read from actual project outputs. Add personal details and tailor each version to the actual job description before sending.

### Day 28: project talk and mock interview

Creates a ten-minute talk timeline, ten mock questions, and a recording checklist. You must record and review yourself; the script cannot do that honestly.

### Day 29: weakness remediation

Uses actual model/dependency status to identify gaps: SQL timing, PyTorch versus tree-model performance, Transformer weight availability, Spark sample limits, and the public-data limitations. It creates a targeted practice list.

### Day 30: final acceptance

Checks source files, outputs, model weights, portfolio files, and application templates. It creates an application tracker and announcement-information template with source, date, evidence link, verification status, and reviewer fields.

## Week 4 acceptance

- A timed SQL test exists and a human score is recorded.
- An end-to-end report can be reproduced from project data.
- Portfolio README, data dictionary, limitations, charts, dashboard, and model evidence are organized.
- Twenty data and twenty AI interview questions are prepared.
- Three targeted resume versions exist with real project metrics and no unsupported claims.
- A ten-minute talk and mock-interview checklist are ready.
- Weaknesses are documented with concrete remediation tasks.
- Final acceptance, application tracker, and announcement template are ready.
